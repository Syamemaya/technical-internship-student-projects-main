# 实习经历与项目提交

公开学生仓只提供学生可见的记录契约，不生成报告、不保存评分、不采集身份映射，也不包含导师测试或内部评价字段。

## 两条证据线

### 实习经历

实习期间可以同时推进多个日常任务。每个任务使用 pseudonymous Task ID，并可以拆成多个 Node：需求与基线、实现、实验、评审、复盘或其他可检查节点。任务记录回答“实习期间做过哪些工作、每一步产生了什么证据”，不要求把所有任务合并成一个项目。

使用 [实习经历记录模板](../templates/internship-experience.md) 维护长期记录，用 [日报模板](../templates/daily-log.md) 记录单个节点。Task ID 和 Node ID 不能包含真实姓名、联系方式或其他身份信息。

### 正式项目提交

学生仍然只选择一个主项目完成 Core。正式项目提交回答“所选项目是否完成、如何运行、如何验证、有哪些限制”，至少包含：

- 所选项目的代码与测试；
- Notebook、实验或论文复现证据（按项目卡要求）；
- 运行命令、验证结果和已知问题；
- Pull Request/CI 链接（如有）；
- `SUBMISSION.md` 和 `AI_USE.md`。

使用 [项目提交说明模板](../templates/student-submission.md)。日常任务可以在其中填写关联的 Task ID，但不要把完整日报复制进正式提交。

## Git 与 CI

Git commit、Pull Request 和 GitHub Actions 是项目证据的一部分。学生只需提供公开链接或简短定位信息；不要粘贴访问 Token、邮箱、原始 CI 日志、私有数据或凭据。导师侧会从远端仓库核对提交和 CI 状态，公开学生仓不保存最终评分或分发报告。

## 复盘材料

`SUBMISSION.md` 中的“学员收获、建议、推荐”是学生自述，不是自动评分字段。导师可以在审核后将合适内容复制到私有记录；公开仓本身不保存导师评语、能力分数、岗位判断或身份映射。

## 最小隐私检查

提交前确认：

1. 所有 Task ID、Assignment ID 都是 pseudonymous 且不含真实身份；
2. 没有 API Key、Token、邮箱、手机号、简历、面试记录或未脱敏数据；
3. 正式项目提交与日常经历记录边界清楚；
4. 代码、测试、Notebook、运行命令和 CI 证据可以被复现；
5. `AI_USE.md` 已披露实际使用并记录验证方式。
