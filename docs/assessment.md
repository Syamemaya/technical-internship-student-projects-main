# 学生项目评价

> 已确认：Core 完成且总分达到 60 分为培训完成，85 分为优秀；人才库和留用判断独立记录。

统一评价结构如下：

| 维度 | 分值 | 重点 |
|---|---:|---|
| Core 完成 | 40 | 主功能、主实验或主复现可运行 |
| 验证与可重复性 | 25 | 测试、参数、运行入口和证据 |
| 工程记录 | 20 | 结构、Git、文档和已知问题 |
| 现场说明与复盘 | 15 | 能解释决策、失败和下一步 |

Core 是独立门槛：总分较高但主流程没有完成时，只能记录为部分完成。截图只能辅助说明，不能替代代码、测试、运行记录和现场解释。

## 实习经历与正式项目提交

学生可以在实习期间记录多个日常任务，每个任务包含多个可检查节点；这些记录用于还原实践过程，不会自动变成第二个项目，也不改变“从对应等级三选一完成一个主项目”的规则。正式验收仍以一个所选主项目的 Core 提交为中心。

实习经历记录和正式项目提交分开维护：前者使用 Task/Node 记录日常开发、学习、分析或协作，后者使用 `SUBMISSION.md` 汇总项目代码、测试、Notebook、运行命令、已知问题和复盘。Git/CI 链接可以同时作为两者的证据，但不能替代正式提交材料。

## 结果分层

- `Core 完成 + 总分 >= 60`：培训完成；
- `Core 完成 + 总分 >= 85`：优秀；
- 其他情况：记录为部分完成，并写明下一步补救任务；
- 人才库、留用或后续岗位判断单独记录，不从本表自动推导。

如果使用 AI，必须提交 `AI_USE.md`，并在现场说明一个被拒绝或改写的 AI 建议及其验证方式。
